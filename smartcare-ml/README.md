# SmartCare ML — triage service

> The AI provides assistive risk assessment and suggests an appropriate medical
> specialty. **It is not a diagnostic system.**

A small FastAPI service with two scikit-learn models we train ourselves, wrapped
in a rules safety layer. It implements the `POST /triage` contract the NestJS
backend already speaks (`src/ai/providers/ml-http.provider.ts`). Design and
rationale: [`docs/AI-PLAN.md`](../docs/AI-PLAN.md).

```
request ─► 1. safety layer      red-flag keywords (EN + AR) → CRITICAL, always wins
           2. specialty model   TF-IDF + Logistic Regression → specialty + confidence
           3. risk model        Random Forest on tabular features → LOW…CRITICAL
           4. rule floors       severe / ≥3 symptoms / vulnerable age / chronic illness
```

The models can raise a risk level the rules set, never lower it. The risk model
may also declare an emergency on its own when it is given a full description
and no red-flag keyword matched.

## Quick start

```bash
cd smartcare-ml
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt

python -m src.download_data       # two Kaggle datasets + DDXPlus → data/raw/
python -m src.prepare             # clean, map disease → specialty, split 80/20
python -m src.train_specialty     # → models/specialty.joblib
python -m src.train_risk          # → models/risk.joblib
python -m src.evaluate            # → reports/metrics.md + charts
pytest                            # golden cases

uvicorn src.service:app --host 127.0.0.1 --port 8000
```

The trained models in `models/` are committed, so the service starts without
retraining. Interactive docs: <http://localhost:8000/docs>.

Connect the backend: set `AI_SERVICE_URL=http://localhost:8000` in the NestJS
`.env` and restart it. Triage responses then carry `"engine": "ml-service"`;
if this service is down they fall back to `"rules-fallback"`.

## Results

See [`reports/metrics.md`](reports/metrics.md) — regenerated by

## How a response is produced

| Step | Where | Notes |
|---|---|---|
| Arabic → English | `src/textutil.py`, `data/ar_en_dictionary.json` | Offline dictionary, longest phrase first. Models are English-only. |
| Red flags | `src/safety.py`, `data/red_flags.json` | Same keywords as the NestJS engine, checked on the raw text **and** its translation. Any match → `CRITICAL`. |
| Specialty | `src/engine.py` | Full descriptions: model answer when confidence ≥ 0.30, otherwise keyword rules (`data/specialty_keywords.json`), otherwise `internal medicine`. Short inputs (≤ 8 words, fewer than 3 symptoms): keyword rules first, then the model. |
| Risk | `src/engine.py`, `src/features.py` | Model prediction (symptom severity weights, patient context, specialty probabilities), never below the rule floor. On a short input the model answers `MODERATE` at most; with nothing it recognizes it gives no opinion. On a full description it may declare `CRITICAL` without a red flag (`ML_MAY_DECLARE_EMERGENCY = True`). |
| Explanation | `reasons` | Confidence, the words that drove the specialty, and every rule that fired. |

`tests/test_triage.py` fails if `red_flags.json` or `specialty_keywords.json`
drift from `rules.provider.ts` — change both together.

## Honest limitations (say these before the committee asks)

- **`data/specialty_map.csv` is reference-reviewed, not clinician-approved.**
  Every row has its ICD-10 code and the basis of its acuity; the review and
  its references are in [`data/SPECIALTY_MAP.md`](data/SPECIALTY_MAP.md). The
  acuity of DDXPlus conditions starts from that dataset's own severity rating
  (1 → CRITICAL, 2 → HIGH, 3–4 → MODERATE, 5 → LOW), with eight documented
  changes.
- **Risk labels are silver labels.** No public dataset has triage risk levels,
  so they are derived: disease acuity from the table above plus simulated
  patient context and the rules engine's floors (`silver_label` in
  `src/train_risk.py`). The risk metrics measure how well the model recovers
  that scheme from symptoms alone — not agreement with real triage nurses.
- **Mostly synthetic data.** Symptom2Disease is ~1,150 short texts for 24
  diseases, the checklist dataset ~300 distinct rows, and DDXPlus ~2,500
  synthetic patients assembled from a fixed phrase list. Accuracy on DDXPlus
  rows is inflated by that shared wording; the same conditions in a patient's
  own words are recognized less reliably. Specialties with no training disease
  (ophthalmology…) are reachable only through the keyword fallback.
- **The headline accuracy is for diseases the model has seen.** On a disease
  removed from training entirely, specialty accuracy drops to about 50% — and
  adding DDXPlus did not improve that for the Kaggle diseases (47.8% → 46.4%
  in the controlled comparison in `reports/metrics.md`). Quote both numbers.
- **Red-flag rules over-call emergencies by design.** Any mention of "chest
  pain" or "shortness of breath" is CRITICAL, as in the NestJS engine, so the
  full service flags about 28% of non-urgent test requests as urgent.
- **Model-declared emergencies were measured on full descriptions only.** Of
  208 truly CRITICAL test requests the red-flag rules alone report 175; with
  the model it is 204, and none of the 29 emergencies the model added was
  false. Short inputs never get an emergency from the model.
- **Arabic is dictionary-based.** Words missing from the dictionary are ignored
  by the models (red-flag keywords still match on the raw text).

## Deploy (VPS, next to the API)

```bash
bash smartcare-ml/deploy.sh        # first install and every update
# then, in the API's .env:  AI_SERVICE_URL=http://localhost:8000
pm2 restart smartcare-api --update-env
```

`deploy.sh` creates the virtual environment, installs the five runtime
packages, runs `src/smoke_test.py` (models load and answer correctly) and
only then (re)starts the `smartcare-ml` PM2 process. It needs Python ≥ 3.11.
Details: [`docs/DEPLOYMENT.md`](../docs/DEPLOYMENT.md), section 6.

Internal-only: bound to 127.0.0.1, no nginx change. `requirements.txt` pins
scikit-learn to the version that trained the `.joblib` files.

For presenting the project: [`docs/AI-EXPLAINED.md`](../docs/AI-EXPLAINED.md).
